# PPT 大纲（20 页，16:9）

> 硬性要求：≤20 页、16:9、≤50MB；匿名评审，不出现学校/姓名/Logo。
> 建议每页 1 个核心观点，图多字少；演示截图要能看到 Agent 轨迹和审批。

## 1. 封面
- 作品名：知账 · 家庭消费健康 Agent
- 一句话：从记一笔，到做对下一步。
- 匿名标识：通用赛道 · 消费领域 / 参赛团队
- 画面：产品首页 + Agent 工作台截图

## 2. 真实痛点
- 记账 App 记了 3 年，还是存不下钱。
- 账单散在微信、支付宝、银行卡、截图、待办里。
- 预算设了不执行；订阅悄悄涨价；目标没有复盘。
- 一句话：**记录不等于改变。**

## 3. 用户与场景
- 目标用户：大学生、初入职场青年、两人小家庭。
- 三个故事：
  - 小林：每天一杯咖啡，月底餐饮超支。
  - 小周：视频会员涨价 20%，忘了取消。
  - 小家庭：想 3 个月存 3000 去旅行，不知道怎么拆。
- 每个故事对应一个英雄场景。

## 4. 方案概览
- 不是“又一个记账 App”，而是消费健康 Agent。
- 感知 → 记忆 → 规划 → 行动 → 反思 → 主动。
- 关键差异：**多步行动闭环 + 审批/审计 + 可解释轨迹**。

## 5. Agent 能力
- 感知：文本、截图、语音（需配置 ASR）、订阅、待办。
- 记忆：画像、目标、商户→分类纠正、审批历史。
- 规划：拆解目标，信息不足先澄清。
- 行动：读写工具分离，写操作先出 diff。
- 反思：执行后校验，周/月复盘。
- 主动：预算漂移、订阅涨价、目标延期。
- 画面：能力六边形 + 真实 trace 截图。

## 6. 技术架构
- uni-app（H5/App）+ FastAPI + SQLite/MySQL。
- Agent Runtime：orchestrator / tools / policy / memory / trace / proactive。
- 大模型：OpenAI 兼容接口，账单解析用模型，数字计算用 SQL。
- 状态机：propose → approve → execute → verify → audit。
- 画面：架构图（不要放密钥）。

## 7. 场景 1：一句话/截图记账 → 预算冲击 → 审批
- 用户说“午饭花了 32 元，微信付的”。
- Agent 解析 → 查预算 → 发现餐饮将超支 12 元 → 提出调配 + 任务。
- 用户批准 → 写账单、调预算、建任务 → 可撤销。
- 画面：真实截图，能看到工具轨迹、diff、批准/拒绝按钮。

## 8. 场景 2：订阅体检 → 涨价/低频 → 拒绝后重规划
- Agent 扫描订阅，发现视频会员涨价 20%、健身会员低频。
- 给出年化影响和暂停方案。
- 用户拒绝 → Agent 不重复原方案，改为“降级 + 观察一个月”。
- 画面：拒绝后生成替代审批的 trace。

## 9. 场景 3：目标规划 → 预算/任务 → 周复盘
- 用户说“3 个月存 3000 去旅行”。
- Agent 查近 3 个月收支 → 判断可行性 → 压缩可自由支配预算 → 建目标 + 每周复盘任务。
- 一周后复盘实际 vs 计划，偏离时重规划。
- 画面：目标进度 + 预算调整 + 任务。

## 10. 可信设计
- 数字只来自 SQL/工具，每个数字带来源和 `as_of`。
- 写操作必须审批；展示 diff、影响金额、过期时间。
- 审批幂等；执行后可撤销；全程审计。
- 不展示原始 CoT，只展示工具轨迹。
- 画面：审批卡 + trace + undo。

## 11. 安全与合规
- 只用合成演示数据；不接真实银行/支付宝/微信账号。
- 敏感文本脱敏；音频转写后删除；日志不含密钥。
- 明确边界：不做投资建议、不代客理财、不自动转账。
- 数据地图、保留期限、删除/导出、第三方模型披露。
- 画面：数据流图（最小化）。

## 12. 评测方法与结果
- 100 条任务，8 类：查询、记账、订阅、目标、预算、安全、澄清、多步骤；dev/test 各 50。
- 指标：任务完成、工具选择、参数、金额一致性、审批一致性、未审批写入、延迟、成本。
- 当前自测：100/100 通过；工具 100%、参数 100%、审批一致性 100%、未审批写入 0；平均 926ms，P95 4.9s（见 `evaluation.md`）。
- 另有：流程/异常 94 项、多轮 53 项、决策模拟 62 项、CSV 47 项。
- 说明：这是团队自测，不是官方评分，也不是第三方认证。
- 画面：分类通过率柱状图 + 延迟/口径表。

## 13. 用户验证
- 5–15 名目标用户，3 个任务：记账、订阅体检、目标规划。
- 记录任务耗时、错误、SUS、访谈原话。
- 对比：手动 vs Agent；是否愿意继续用。
- 画面：前后对比图 + 匿名引语。
- 注：若 11/10 前样本不足，如实写“初步可用性测试”，不要编造。

## 14. 成本与性能
- 模型路由：账单解析用轻量模型；其余用规则/SQL。
- 100 条评测：平均 926ms，P95 4.9s；查询类通常 <100ms；记账含模型解析 2–6s。
- 成本估算：100 条约 ¥0.042（后端估算，不是真实 token 账单）；每日限流 30 次/用户。
- 缓存、降级、超时重试；模型未配置/超时自动走规则。
- 画面：成本/延迟表 + 解析来源（模型 21 / 规则 8）。

## 15. 竞品对比
- 支付宝/微信：支付入口强，缺跨平台家庭 Agent。
- 随手记/鲨鱼：记录强，缺多步规划与行动。
- Copilot Money：审批优先，值得学习；英文/单用户为主。
- Rocket Money：主动订阅行动强；国内场景不同。
- Monarch：家庭数据 + 权限层；我们做中文消费健康。
- 画面：2×2 定位图（记录↔行动，单点↔家庭）。

## 16. 创新点
- 中文跨平台家庭账单 + 可审批多步行动 + 可解释轨迹。
- 消费健康定位，避开投资建议合规风险。
- 手账风 UI + Agent 工作台，降低使用门槛。
- 规则用于触发，模型用于理解/表达，工具用于执行。

## 17. 可落地性

- B2B2C：校园/社区/银行合作，匿名聚合洞察。
- 部署：Docker + HTTPS，数据可本地化。
- 数据接入路线：截图/文本 → CSV → 开放银行/账单 API。
- 画面：部署架构 + 商业模式一页。
