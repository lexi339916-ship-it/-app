# 6 分钟演示视频脚本

> 硬性要求：≤6 分钟、MP4、≤300MB；匿名，不出现学校/姓名/Logo。
> 原则：真实录屏、真实数据、保留审批和失败路径；不要只放 PPT。

## 0:00–0:30 钩子

**画面**：记账 App 的流水列表快速滚动，停在“本月结余”。

**旁白**：
“这是我记了 3 年的账。每一笔都记了，但我还是不知道钱去哪了。记录不等于改变。我们想做的，是一个能帮我做对下一步的消费健康 Agent——知账。”

## 0:30–1:10 痛点与用户

**画面**：微信/支付宝/银行卡/截图/待办五个图标散开；切到用户故事卡片。

**旁白**：
“账单散在微信、支付宝、银行卡、截图和待办里。预算设了不执行，订阅悄悄涨价，目标没有复盘。我们聚焦三类人：大学生、初入职场青年、两人小家庭。今天展示三个真实任务。”

## 1:10–2:00 方案与架构

**画面**：架构图；Agent 工作台首页。

**旁白**：
“知账不是又一个记账 App。它把感知、记忆、规划、行动、反思串成一个闭环：自然语言或截图进来，Agent 查真实数据、给出计划，写操作先出 diff，用户批准后才执行，执行后可撤销、可审计。规则负责触发，模型负责理解和表达，SQL 负责数字。”

## 2:00–3:00 场景 1：记账 → 预算 → 审批 → 执行

**画面**：Agent 页输入“午饭花了 32 元，微信付的”，点击运行；出现计划、工具轨迹、审批卡。

**旁白**：
“我说一句午饭 32 元。Agent 先解析，再查本月餐饮预算：已经花了 1180，预算 1200，这笔会超 12 元。它提出两个动作：从交通调配 50 元，创建一个本周控制餐饮的任务。注意，它没有直接写库，而是等我确认。我批准——账单、预算、任务一起写入，轨迹里能看到执行和校验。现在后悔了，可以一键撤销。”

**画面**：点击批准；状态变为已完成；点击撤销；数据恢复。

## 3:00–3:50 场景 2：订阅体检 → 拒绝 → 重规划

**画面**：输入“帮我检查订阅”；展示涨价/低频卡片。

**旁白**：
“第二个任务：订阅体检。Agent 发现视频会员从 25 涨到 30，近 90 天只用 1 次；健身会员近 90 天一次没用，年化 2388。它建议暂停视频会员。假设我不想暂停——我点‘先不要’。Agent 没有重复原方案，而是改成‘先观察一个月’，并创建复盘任务。这就是可验证的重规划：不是重复原方案，而是生成替代方案。”

**画面**：点击拒绝；出现替代审批；点击批准；任务创建。

## 3:50–4:20 场景 3：目标规划 → 预算/任务 → 周复盘

**画面**：输入“3 个月存 3000 元去旅行”；展示可行性、预算调整、目标卡。

**旁白**：
“第三个任务：我说 3 个月存 3000 去旅行。Agent 查近 3 个月收支，判断可行；把娱乐、购物、餐饮各压一点，创建旅行基金和每周复盘任务。它会先生成每周复盘任务；后续版本会自动对比实际和计划，偏离时再调整。目标不是一句口号，而是可执行的预算和任务。”

## 4:20–5:00 新增能力快剪：健康 / 多轮 / 模拟 / CSV

**画面**：首页消费健康卡 → 健康报告五项指标 → Agent 三轮追问 → 决策模拟（5000 元）→ CSV 预览导入。

**旁白**：
“除了三个英雄场景，我们还补了四块：消费健康诊断，五项指标全部有公式、来源和时间；多轮对话，同一会话里说‘不想动交通’‘只调整 100’，旧审批自动替代；消费决策模拟，买 5000 元之前先算预算和目标影响；CSV 导入，微信、支付宝和通用表头先预览去重，再确认写入。所有写操作仍然要审批。”

## 5:00–5:40 评测与证据

**画面**：评测报告图表；工具轨迹；成本/延迟表。

**旁白**：
“我们用 100 条任务做了自测，覆盖查询、记账、订阅、目标、预算、安全、澄清和多步骤，当前 100 条全部通过；工具选择、参数、审批一致性都是 100%，未审批写入为 0；平均 0.93 秒，P95 4.9 秒。另有 94 项审批/异常断言、53 项多轮、62 项模拟、47 项 CSV。每次写入都有审批、幂等和撤销；每个数字都有来源和时间。这不是官方评分，是我们的可复现证据。”

## 5:40–6:00 愿景与收尾

**画面**：产品首页 + 团队匿名标识。

**旁白**：
“我们希望每个普通家庭，都有一个看得懂、敢交给它办事的消费健康 Agent。知账，从记一笔，到做对下一步。谢谢。”
